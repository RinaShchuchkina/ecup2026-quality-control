# Данные

Датасет предоставляется организаторами. Исходные файлы — `data.csv` и каталог
изображений — в репозиторий не входят: одни только изображения занимают около
9 ГБ. Этот каталог в git пустой, положите данные сюда вручную перед запуском.

Состав `weights/model_v1.pkl`. Помимо обученных коэффициентов файл содержит
retrieval-индексы, построенные по обучающей выборке.
<img width="677" height="262" alt="image" src="https://github.com/user-attachments/assets/150949d1-6cb0-41b2-a83a-3d7b98ac0c11" />

Это 9378 нормализованных строк «название + описание», 7983 и 6955 записей для
сокращённых текстовых ключей, 32951 хэш изображений и 13199 записей dHash.
Тексты товаров из них восстанавливаются, поэтому файл содержит производную
от данных конкурса.

Отсюда следствие: репозиторий не может публиковаться открыто. Пункт 2.12 правил
запрещает публиковать решение или его часть без письменного согласия
организатора, а вместе с индексами публикация затронула бы и данные.
Репозиторий передаётся жюри приватно.

## Куда класть

Корень данных задаётся переменной окружения `ECUP_DATA`, значение по умолчанию —
`data` (относительно корня репозитория, то есть этот каталог).

```
export ECUP_DATA=data
```

Переменную читают `src/prepare_data.py`, `src/build_image_cache.py`,
`src/train_text.py` и `src/train_lora.py`. Аргументы `--data-csv` и `--images`
позволяют переопределить пути точечно, если данные лежат на отдельном диске.

## data.csv

12971 строка. Первая колонка — безымянный индекс pandas: `prepare_data.py`
читает файл как `read_csv(..., index_col=0)`, а `predict.py` отбрасывает
колонку `Unnamed: 0`, если она есть.

| Колонка       | Описание                                                          |
| ------------- | ----------------------------------------------------------------- |
| `id`          | Идентификатор товара; совпадает с именем подпапки в `images/`      |
| `name`        | Название товара                                                    |
| `description` | Описание, может содержать HTML-разметку и пустые значения          |
| `category`    | Категория товара (`БАД`, `Легковоспламеняющиеся`)                  |
| `label`       | Бинарная целевая метка, 0 или 1                                    |

Помимо перечисленных, в файле присутствуют колонки с аннотациями фотографий.
Текущий пайплайн их не использует и читает изображения напрямую из `images/`.

Пропуски в `name` и `description` заполняются пустой строкой при загрузке, так
что предобработка CSV не нужна — файл кладётся как есть.

## images/

Одна подпапка на товар, имя подпапки — значение `id` из `data.csv`. Внутри до
нескольких JPEG-файлов; имена произвольные, порядок обхода — лексикографическая
сортировка по имени файла. Код принимает расширения `.jpg`, `.jpeg`, `.png`,
`.webp` (регистр не важен).

Товар без подпапки или с пустой подпапкой — допустимая ситуация: такие записи
обрабатываются только текстовыми ветками модели.

По умолчанию в обучающую выборку берётся не более 5 изображений на товар
(`prepare_data.py --max-imgs`).

## Данные на инференсе

`src/predict.py` получает путь к тестовому CSV через `--test_data_path` и ищет
изображения в каталоге `images/` **рядом с этим CSV**, а не в `ECUP_DATA`.
Тестовый набор должен повторять структуру выше:

```
<каталог с тестовыми данными>/
├── test.csv
└── images/
    └── <id>/...
```

## Что порождается из данных

Производные артефакты пишутся в каталог `ECUP_OUT` (по умолчанию `runs`) и тоже
не хранятся в git:

| Артефакт             | Кем создаётся            | Что это                                   |
| -------------------- | ------------------------ | ----------------------------------------- |
| `imghash.pkl`        | `prepare_data.py`        | MD5 всех изображений, кэш дедупликации     |
| `families.pkl`       | `prepare_data.py`        | Товары, сгруппированные в семейства-дубли  |
| `labels_folds.csv`   | `prepare_data.py`        | Метки и разбиение на фолды                 |
| `sft_data.jsonl`     | `prepare_data.py`        | Выборка для дообучения VLM                 |
| `cache/imgs_256.npy` | `build_image_cache.py`   | memmap-кэш картинок 256x256 для vision     |

Первым шагом всегда запускается `src/prepare_data.py`: остальные скрипты
рассчитывают на уже готовые `labels_folds.csv` и `families.pkl`.
