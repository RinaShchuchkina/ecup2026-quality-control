# Манифест репозитория

Опись того, что лежит в репозитории: за что отвечает каждый файл, откуда взялись
веса, чем обучен каждый артефакт. Размеры измерены на диске.

Входные данные организаторов в репозиторий не входят. Базовые модели тоже:
они берутся из каталога общих моделей внутри образа жюри и никогда не
скачиваются во время инференса — запуск офлайновый.

## код (`src/`, 128 КБ)

| файл | строк | назначение |
|---|---|---|
| `predict.py` | 690 | инференс, единая точка входа для обеих конфигураций |
| `train_lora.py` | 292 | SFT LoRA-адаптеров поверх мультимодальной и текстовой базовых моделей |
| `train_vision.py` | 276 | обучение визуальной ветви EVA-02 по фолдам |
| `train_text.py` | 237 | текстовая модель и сборка `model_v1.pkl` со всеми индексами |
| `prepare_data.py` | 189 | хэши картинок, семьи дублей, фолды, обучающий jsonl |
| `comments.py` | 130 | объяснение вердикта 50–300 символов и валидатор формата ответа |
| `encoder_branch.py` | 117 | инференс текстового энкодера (в зачётных конфигурациях выключен) |
| `eva_branch.py` | 109 | инференс визуальной ветви, усреднение по пяти фолдам |
| `build_image_cache.py` | 87 | предварительный кэш изображений в один массив |
| `vision.py` | 80 | подготовка изображений под мультимодальную модель |
| `rules_lv.py` | 79 | семантический роутер категории «Легковоспламеняющиеся» |
| `analyzers.py` | 75 | ручной TF-IDF и 14 regex-признаков, без зависимости от sklearn |
| `prompts.py` | 3 | два промпта с правилами категорий |
| `metadata.json` | — | образ и точка входа для платформы |

`analyzers.py` дублирует токенизацию и трансформацию sklearn вручную, потому что
инференс не должен зависеть от версии библиотеки: расхождение с эталонной
реализацией проверено и составляет 1e-16. Обучение при этом использует sklearn.

`vision.py` заменяет служебную утилиту разработчиков базовой модели: в образе
жюри нет ни `requests`, ни `torchvision`, а официальный препроцессор тянет оба.

### порядок ветвей в `predict.py`

1. текстовая модель — базовая вероятность для всех строк;
2. LoRA-ветви, взвешенно подмешиваются к текстовой внутри категории;
3. визуальная ветвь, забирает свою долю и пропорционально ужимает остальные;
4. правило «не является БАД» — жёсткий ноль;
5. точный retrieval по текстовым ключам и хэшам картинок — жёсткое
   переопределение при единогласии группы;
6. переопределение по перцептивному хэшу, только для непокрытых точным поиском;
7. нечёткий char-TFIDF по названию;
8. семантический роутер ЛВ, последним и только там, где retrieval промолчал;
9. пороги по категориям, генерация комментария, валидация формата.

Ветвь, заявленная в конфигурации, обязана загрузиться: при отказе запуск падает,
а не продолжается молча с перераспределёнными весами. В лог печатаются
фактические доли живых ветвей. Это следствие разбора отправки, где тихое
изменение весов стоило 0.086 macro.

## конфигурации (`configs/`, 8 КБ)

Два зачётных решения различаются составом ветвей, а не кодом.

| параметр | `solution_1.json` | `solution_2.json` |
|---|---|---|
| адаптеры | `adapter`, `adapter_q35t` | `adapter` |
| веса адаптеров, БАД | 0.3 + 0.3 | 0.5 |
| веса адаптеров, ЛВ | 0.25 + 0.5833 | 0.5 |
| визуальная ветвь | 0.4 на ЛВ | нет |
| пороги БАД / ЛВ | 0.37 / 0.41 | 0.37 / 0.41 |
| ключи retrieval, БАД | td, nd | td, nd |
| ключи retrieval, ЛВ | td, nd, w5 | td, nd, w5 |
| картинки в голосовании | только БАД | нет |
| перцептивный хэш | нет | ЛВ, симметрично на БАД |
| правило «не является БАД» | нет | да |
| роутер ЛВ | нет | да |
| kNN | выключен | выключен |

Первая конфигурация ставит на дополнительные обученные ветви, вторая — на
правила и поиск дублей поверх исходной связки. Разведение сделано намеренно:
две финальные отправки не должны падать по одной и той же причине.

### `model_v1.pkl` — 45 811 390 байт

Один pickle, восемь ключей, всё нужное для CPU-части инференса.

| ключ | содержимое |
|---|---|
| `categories` | по одной логистической регрессии на категорию |
| `text_index` | 9378 ключей: нормализованные название и описание |
| `text_index_nd` | 7983 ключа: название без цифр |
| `text_index_w5` | 6955 ключей: первые пять слов названия |
| `img_index` | 32951 хэш изображений |
| `dhash_votes` | 13199 перцептивных хэшей с голосами меток |
| `dhash_votes_cat` | те же голоса, разложенные по категориям |
| `fuzzy_lv` | char-TFIDF матрица названий ЛВ и метки к ним |

В каждой из двух категорийных моделей: словарь слов на 60 000 признаков
(униграммы и биграммы), символьный словарь на 100 000 признаков (n-граммы 3–5
внутри границ слова), 14 regex-флагов — итого вектор коэффициентов на 160 014
позиций. TF-IDF с сублинейным tf, логистическая регрессия C=4,
`class_weight="balanced"`, 2000 итераций. Пороги 0.37 и 0.41 хранятся рядом
с коэффициентами.

Значение в индексе — среднее меток группы. Переопределение применяется только
при единогласии, то есть когда среднее равно ровно 0 или 1.

### `adapter/` — 66.6 МБ, LoRA к Qwen3-VL-2B-Instruct

r=16, alpha=32, dropout 0.05, `bias=none`, целевые модули — проекции внимания
и MLP только в языковой части (`q_proj`, `k_proj`, `v_proj`, `o_proj`,
`gate_proj`, `up_proj`, `down_proj`), тип задачи CAUSAL_LM. Сохранён библиотекой
peft 0.19.1.

Обучение: одна эпоха по всем строкам без отложенного фолда, батч 2 при
накоплении 8 шагов, lr 1e-4, до 4 изображений на товар, 262 144 пикселя,
3072 токена контекста, троекратный оверсэмплинг положительных ЛВ, seed 42.
Ответ модели — одно слово «да» или «нет»; на инференсе берётся softmax по
логитам этих двух токенов на позиции ответа.

Обучен на исходных метках, без семантической чистки: адаптер, обученный
на чищенных метках, переносился на тест хуже.

### `adapter_q35t/` — 81.0 МБ, LoRA к текстовой модели Qwen3.5-4B

Те же гиперпараметры LoRA (r=16, alpha=32, dropout 0.05, те же целевые модули),
peft 0.20.0. Отличие в подаче: изображения отключены полностью, контекст 2048
токенов. Так сделано вынужденно — мультимодальное дообучение модели 4B на
доступном оборудовании требовало порядка 11 часов на фолд.

### `eva/` — пять файлов по 163.6 МБ

Архитектура timm `eva02_base_patch14_224.mim_in22k`, голова на один логит,
веса встают в модель со строгой проверкой имён. Обучалась только категория
«Легковоспламеняющиеся» — на БАД визуальная ветвь не даёт ничего поверх текста.

Один обучающий пример — одна фотография, метка берётся у товара. Вход 224
пикселя, белый паддинг с сохранением пропорций. Аугментации: случайный кроп
0.65–1.0, горизонтальное отражение, мягкий цветовой джиттер и, отдельно,
пересжатие в JPEG с качеством 40–95 с вероятностью 0.5 — последнее прямо
моделирует то, что организаторы пересжимают тестовые изображения.

Оптимизация: AdamW, lr 1e-4, послойное затухание lr 0.75, weight decay 0.05,
drop path 0.1, батч 64, ровно 6 эпох без отбора лучшей по валидации.
Восьмикратный оверсэмплинг положительных. Пять фолдов по семьям дублей, семьи
не разрезаются. На инференсе прогноз — среднее по пяти фолдам, товар без
фотографий ветвь пропускает.

Фиксированное число эпох выбрано не из удобства: отбор эпохи по валидационному
фолду давал на ЛВ AUC 0.8768 против 0.8951 у фиксированных шести.

### служебное замечание по адаптерам

Библиотека peft кладёт рядом с весами автоматический `README.md`, в который
записывает путь к базовой модели на машине, где шло обучение. В отправляемый
архив эти файлы не попадают: упаковщик их удаляет и падает, если находит
в архиве локальные пути. При любой пересборке пакета проверка обязательна.

## сборка пакета сабмита

Готовые архивы в репозиторий не включены: они целиком собираются из его
содержимого и лишь дублировали бы веса. Сборка — `src/pack_submit.py`:

    python3 src/pack_submit.py --config configs/solution_1.json --out submit_1.zip
    python3 src/pack_submit.py --config configs/solution_2.json --out submit_2.zip

Размеры получаемых архивов: 911 МБ для первого решения, 79 МБ для второго.

Пакет самодостаточен: `run.py` (копия `src/predict.py` с плоскими импортами),
`src/`, `model_v1.pkl`, адаптеры, конфигурация, `metadata.json` и `vendor/`.
Дублирование намеренное — пакет должен запускаться без репозитория вокруг.

В `vendor/` лежат peft 0.20.0 и timm 1.0.27: в образе жюри их нет.

Перед записью архива скрипт проверяет отсутствие локальных путей в текстовых
файлах и отсутствие не-ASCII символов в именах файлов. Обе проверки появились
после реальных сбоев: путь к домашнему каталогу попадал в карточку адаптера,
а кириллица в имени файла весов ломала распаковку на платформе.

| transformers | 5.14.1 |
| torch | 2.10.0 |

Базовые модели, которые пакет ожидает найти в образе: мультимодальная
Qwen3-VL-2B-Instruct и текстовая Qwen3.5-4B. Веса EVA-02 обучены нами
от предобученного чекпоинта ImageNet-22k и лежат в репозитории целиком —
базовый чекпоинт при инференсе не нужен.

Регламент платформы: до 40 минут на приватный сплит примерно из 3800 товаров,
архив до 5 ГБ, доступ в сеть закрыт.

## пустые каталоги

`data/` и `train/` пусты. Данные принадлежат организаторам и в репозиторий
не включаются; обучающие скрипты лежат в `src/` рядом с инференсом, потому
что делят с ним токенизацию, препроцессинг изображений и правила.
